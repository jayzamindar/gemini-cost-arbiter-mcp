PHASE 3: DATA CONTRACTS & SCHEMAS (app/schemas.py)
--------------------------------------------------------------------------------
Prompt:
"Implement production-grade, zero-boilerplate Pydantic v2 data models in `app/schemas.py` 
supporting multi-dimensional telemetry ingestion, remediation action synthesis, and 
MCP payload wrapping.

Requirements:
- Enums: CloudResourceType (EC2, RDS, S3), ActionType (RIGHTSIZE_INSTANCE, STOP_INSTANCE, 
  STOP_DB_INSTANCE, TRANSITION_STORAGE_TIER, TERMINATE, DOWNSIZE, IGNORE).
- Telemetry Models: EC2Metrics (with CPU avg/p95, memory, network, monthly spend), 
  RDSMetrics (CPU, memory, storage allocated/used, connections, Multi-AZ), 
  S3Metrics (storage GB, object count, current storage class, access patterns).

- Remediation Models: RemediationActionItem with safety_risk_score (1 to 5 validation), 
  system_mitigations list (mandatory non-empty if score >= 3), and execution_payload dict.
- RemediationPlan: Aggregated remediation plan with total current spend, projected savings, 
  projected spend, average and max risk score.
- DynamicFallbackModel and module-level __getattr__ fallback for self-healing schema resilience."

PHASE 4: ARBITER ENGINE & MCP INTERFACE (app/engine.py)
--------------------------------------------------------------------------------
Prompt:
"Implement the core asynchronous FinOps orchestrator in `app/engine.py` using Python 3.13+ 
asyncio, httpx.AsyncClient, and Pydantic v2.

Core Capabilities:
1. `GeminiCostArbiterEngine`:
   - Configurable API key, endpoint, timeout, and max acceptable risk.
   - Dual-path arbitration: attempts upstream Gemini 3.8 Flash High / OpenRouter reasoning 
     first, seamlessly falls back to the deterministic heuristic engine on API failure, 503, 
     or timeout.
   - Deterministic Heuristic Engine: rule-based evaluation detecting EC2 low CPU/p95, 
     RDS zero-connection idle instances, and S3 cold storage (>50% infrequent access).
   - In-memory FinOps audit ledger tracking cumulative waste analyzed, savings proposed, 
     and per-resource breakdowns with thread-safe reset.
2. Model Context Protocol (MCP) JSON-RPC 2.0 Gateway:
   - `handle_mcp_message`: Async handler supporting `initialize`, `tools/list`, and `tools/call`.
   - MCP Tools: `analyze_infrastructure_waste`, `generate_remediation_plan`, and `get_finops_audit_summary`.
   - Comprehensive error handling returning standardized JSON-RPC error codes."
